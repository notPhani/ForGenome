01The problem the architecture answers

Variant interpretation is not short of data or of models. It is short of a layer that can hold nine sources' worth of disagreeing records as one coherent, auditable world — and then decide what to look at next.

Three assumptions in the standard stack turn out to be false against real payloads, and each one produced a specific defect we had to fix:

Same reality, different records

gnomAD calls a base 10149822; ClinVar's canonical SPDI calls the same base 10149821. One is 1-based. Nothing in either payload says so.

Relevance ≠ sufficiency

“Does PM2 apply?” is not a document-similarity question. It depends on which clause of the rule is live, which depends on what the evidence turned out to be.

Domain logic in the weights

Push identity, provenance and rule state into the model and every knowledge update becomes a retraining problem, and every model swap a migration.

What the data actually did to us

Comparing ClinVar classifications as strings produced 47 false CONTRADICTS edges on a variant ClinVar itself labels “no conflicts” — because Pathogenic and Likely pathogenic are the same verdict under ClinVar's own concordance model. Linking submissions to conditions from EFetch alone resolved 3 of 22; an ESummary trait-xref crosswalk took it to 14. And identity resolution originally ran before verification, so a rejected batch still polluted the persistent index.

None of these are visible from a schema. They are only visible from the payloads.

02The whole flow, end to end

Six layers. The first three exist and are exercised by 263 tests and a live panel harvest; the last three are specified and deliberately unbuilt. The boundary is drawn where it actually falls, not where it would be flattering.

03Layer 2 — the compiler BUILT

This is the layer that earns the word “compiler” rather than “ETL”. It has a staging phase, a resolution phase, a verification gate, and transactional commit.

3.1Connectors are a registry, not a switch statement

A source joins the system by calling register_connector() once at import time with a ConnectorDescriptor. Nothing in the runner, the planner or the CLI names a connector. Adding one touches its own module and one import line.

The descriptor carries: an adapter (fetch/capabilities/manifest), a build_query(scope, anchor) that returns None when the connector has nothing to say about that scope, a build_emission(raw, ctx) that produces tagged nodes and edges, and requires — the other connectors it hard-depends on. gnomAD declares requires=("clinvar",) because a frequency needs a variant identity to attach to; that single field is what makes the load plan a DAG instead of a sequence.

3.2Source truth, Forge mapping, runtime interpretation

Three boundaries that must not blur, enforced by keeping them in different modules:

  • Source truth — what the payload literally says, parsed into a typed SourceObject per source. No Forge semantics here at all.
  • Forge mapping — how that becomes nodes and edges. Simple fields use declarative MappingRules; genuinely branching structure uses a named EscapeHatch, because ClinVar's VCV/RCV/SCV hierarchy is not expressible as flat field mapping and pretending otherwise produces a worse graph.
  • Runtime interpretation — what a rule concludes from it. dbNSFP emits scores; it must never emit “PP3 satisfied”. That inference belongs to the Operational layer, which can be versioned and audited separately.

3.3Identity is resolved centrally, once

No connector canonicalises its own identifiers. Every candidate node goes through one resolver against a persistent SQLite index, which returns MERGED, REPRESENTS (weak cross-source equivalence, never a silent merge), or UNRESOLVED. The 1-based/0-based coordinate fix lives in exactly one function. The one-hour harvest recorded 8,287 cross-batch merges — the same Disease, Gene or Submitter arriving from different variants and landing on one node.

04Layer 3 — the graph BUILT

It is a knowledge graph. That is not the novel part, and claiming otherwise would be the fastest way to lose a technical audience. What matters is that the vocabulary is small and frozen, so that meaning lives in the ontology rather than in each connector's private conventions.

Two distinctions the vocabulary is protecting

A submitter is not a source. Claim —RELATES_TO[submitted_by]→ Submitter, never SOURCED_FROM. SOURCED_FROM points at a SourceManifest — the actual dataset and version a claim was compiled from.

Support is qualified. SUPPORTS[corroborates] between an observation and a claim is a different assertion from SUPPORTS[satisfies_requirement] between an observation and a rule. One generic predicate for both would make the graph unqueryable for exactly the question the runtime needs to ask.

05Layers 4–5 — attention and context DESIGNED

This is the part that is specified and not implemented. Stating that plainly is worth more than a demo that implies otherwise.

The design objective is precise: not “which nodes are relevant to this query”, but “given what this investigation still has open, which graph transition is worth taking next”. Those are different functions with different inputs.

5.1Why this is not a GNN

A GNN learns a node representation from local structure. That is a genuinely useful thing and may end up inside this layer. But it answers a different question: a GNN embedding of a PopulationFrequency node is the same embedding whether the live question is “is this variant rare?” or “could it disrupt the protein?”. The retrieval objective here is transition utility conditioned on investigation state, which has the state on the input side.

There is also a blunt practical reason it is not built yet: there is no corpus of labelled investigation traces to train on. A rule-and-state formulation is what you build when you have the rules and not the labels.

06One question, two architectures

The clearest way to see the difference is to trace a single real question through both. This example is not hypothetical — it is the end-to-end test that gates the build, and it forced a change to the evaluator.

“Does ACMG criterion PM2 apply to VHL c.499C>T?” PM2 asks whether a variant is absent or at extremely low frequency in population databases.

Where the alternatives win

If the question is open-ended literature synthesis, RAG is the right tool and this architecture is overhead. Forgenome pays off only where an answer must be defensible — where someone will ask which record, which version, which clause.

What this costs

A connector is not a scraper. Each one needs its payload understood well enough to know that faf95_popmax and af are not interchangeable. That is the real price, and it is why six of thirteen connectors are still honest stubs.
